# Auto gateway

Актуально для кандидата 3.9.0; старое описание незавершённого первого коммита заменено.

## Контракт

- Gateway — IPv4 next-hop default route физической Wi-Fi/Ethernet сети. VPN-интерфейс исключается; activeNetwork предпочитается, затем проверяются доступные physical networks.
- Адрес определяется при запуске/возврате UI, обновлении LinkProperties/появлении/потере сети, выборе auto-профиля и включении Auto gateway.
- `gatewayIp` доступен для отображения даже в ручном режиме. При `useGatewayAsHost=true` найденный адрес сразу записывается в Host и JSON выбранного профиля; при false ручной Host не меняется.
- При отключении auto последняя найденная Host сохраняется для ручного редактирования. Отсутствие шлюза не заменяет Host пустотой. Результат старого запроса после смены профиля/нового запроса игнорируется.
- Сервис отдельно проверяет gateway перед подключением. Auto-режим не подключается к устаревшему сохранённому Host при отсутствии реального шлюза. При boot ждёт сеть до 120 секунд и сохраняет фактический Host.

## Важные ограничения

Шлюз не обязательно является прокси-сервером: нужный порт/протокол должен реально работать на роутере/телефоне. Мобильная сеть может не иметь IPv4 gateway. При нескольких одновременно подключённых физических сетях порядок fallback не гарантирует корректного выбора производителя; это требует проверки на конкретной приставке. Ручное изменение Host/порта/профиля не перенастраивает работающий туннель: для применения переподключитесь. В активной auto-gateway сессии изменения самой физической сети применяются автоматически, как описано ниже.

## Код и проверки

`NetworkUtils.kt` → `MainViewModel.refreshGateway()` → `Profile` / SharedPreferences. `ProxyDroidVpnService` резолвит gateway отдельно для фактического соединения.

`GatewayStartupTest` проверяет стартовый auto Host и сохранение ручного Host; `MainScreenTvTest` проверяет фокус и видимость ошибок. Статические contracts — `scripts/check_tv_contract.py`. Wi-Fi/Ethernet/смена реальной сети — device checklist в [TV review](docs/ANDROID_TV_REVIEW.md).

## Восстановление активной auto-gateway сессии

- Наблюдение находится в foreground VPN-сервисе, работает без открытого UI. NetworkCallback + debounce 750ms; резервная проверка каждые 5 секунд на OEM с пропущенными callbacks.
- Изменение Network handle, локального IPv4/prefix или шлюза пересоздаёт TUN/native-сессию только ПОСЛЕ успешной очистки старой. Повторные события с той же сигнатурой не перезапускают VPN.
- Потеря локальной сети закрывает старую сессию и показывает Connecting / ожидание сети в уведомлении. После возвращения шлюза пересоздаётся даже с прежним адресом. Время ожидания после уже успешного подключения не ограничено 120 секундами boot-start; Stop отменяет ожидание.
- Ручной Host и выключенный VPN автоматически не подключаются. Auto режим является снимком фактически запущенной сессии; изменения профиля требуют переподключения. Новый gateway сохраняется только если исходный профиль всё ещё выбран и auto включён.
- Stop/onRevoke отменяют наблюдение. Каждое establish повторно проверяет generation и Android consent. Другой VPN не принудительно останавливается; после revoke наш сервис не захватывает его обратно. Не подтверждённая native cleanup блокирует reconnect.
- Шлюз — лишь адрес, не гарантия прокси/интернета. После восстановления могут потребоваться отдельная диагностика и перезапуск YouTube для его собственных соединений. Не заявляется устранение UDP/QUIC/IPv6 ограничений.
