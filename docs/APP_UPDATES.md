# Обновление приложения и установка APK

## Пользовательский поток

**⋮ → Update app → Stable / Test → Check latest → Download APK**. После успешной проверки скачанного APK установщик Android вызывается автоматически, только пока Activity видима/resumed. Системное подтверждение остаётся обязательным — это не silent install.

Под полосой загрузки после завершения появляется полный фактический `File.absolutePath`, например `/data/user/0/org.proxydroid/cache/updates/proxydroid-v…apk`. Строка не обрезается и переносится; она фокусируема пультом и запускает повторную установку по нажатию / DPAD OK. Доступна и кнопка Install. Повторная скачка не нужна. Файл приватный: обычный файловый менеджер не может открыть этот raw path. Установщику передаётся защищённый `content://` FileProvider URI с временным read grant и ClipData. Это намеренное ограничение, не общая папка Downloads.

Если Android запрещает установку из LocProxyTV, открывается настройка разрешения для приложения (fallback — настройки безопасности ТВ). После разрешения и возврата установка возобновляется. Если установка отменена — APK остаётся, нажмите путь/Install снова. Закрытие диалога отменяет ожидающий запуск; скачивание/проверки не продолжаются как скрытая установка. Кэш может быть удалён Android, пользователем или переустановкой; после process death повторное восстановление каталога пока не обещается.

## Докачка и диагностика 3.8.3

Загрузчик сохраняет частичный APK в приватном кэше `update-downloads/`, вне каталога FileProvider. При обрыве/idle timeout автоматически повторяет запрос до пяти попыток с задержкой; HTTP Range запрашивает только оставшиеся байты. Если сервер не поддерживает Range и возвращает 200, файл перезаписывается целиком, а не склеивается. Content-Range проверяется строго. В диалоге показаны байты, скорость, номер попытки и приблизительное оставшееся время.

**Pause / close** отменяет работу и сохраняет полученные байты; новая проверка того же релиза и **Resume download / verify** продолжают загрузку. Перезапуск процесса сохраняет байты, пока Android не удалил кэш; это не фоновая системная загрузка. Истёкшие GitHub redirects запрашиваются заново. Уже полный файл не скачивается повторно, но проходит все проверки. При несовпадении checksum повреждённые байты удаляются. Медленная сеть не гарантирует успешного скачивания: 15 s connect timeout и 90 s idle read timeout остаются ограниченными.

Подписи: диалог показывает SHA-256 реального установленного сертификата и, после разбора APK, скачанного. Отсутствующая подпись и действительно отличающиеся подписи — разные ошибки. Android 9+ использует signingInfo; если OEM его не возвращает, берётся legacy signatures. Пустой результат никогда не означает разрешённое обновление. Проверка сертификата не отключается.

Если сертификаты действительно отличаются, обновление поверх установки невозможно: возможны debug, исходный upstream APK или другой release key. Сначала сохраните настройки и сравните отпечатки; приложение ничего не удаляет автоматически. Для диагностики нужны текущая версия/build/type и оба SHA-256 из диалога, а не приватный ключ. Переименование отображаемого названия не требует изменения applicationId или ключа и само по себе не исправляет несовпадение подписи.

## Исправление 3.8.1

Ранее download завершался сохранением File, без автоматического перехода, а installer запускался из Application context + NEW_TASK только отдельной кнопкой. Это могло быть неочевидно на ТВ и зависеть от ограничений/OEM handler. Теперь запуск идёт из видимой Activity, сначала ACTION_INSTALL_PACKAGE, при отсутствии обработчика — ACTION_VIEW с MIME APK. Нет предположения о конкретном package name установщика. Конкретную причину сбоя на пользовательской приставке без logcat установить нельзя; изменения закрывают эти известные слабые места.

Перед каждой попыткой выполняется IO перепроверка cache bytes (size/SHA-256), реальных package/version/minSDK/JNI ABI и текущей подписи. Подменённый или удалённый файл не передаётся установщику. Скачивание только HTTPS GitHub с allow-list redirects и лимитами. Отладочные/unsigned APK не предлагаются; downgrade запрещён.

## Диагностика на приставке

1. Выберите Test для текущего RC. Дождитесь сообщения APK verified и полного пути.
2. Подтвердите разрешение неизвестного источника только для LocProxyTV.
3. При возврате ожидайте системный экран установки. Если не появился — выберите строку пути / Install; запишите текст ошибки.
4. Проверяйте обновление **release → release с тем же сертификатом**, без удаления приложения. С debug-подписи обновление невозможно.
5. Для поддержки приложите Android version, модель/прошивку, текущую/целевую версию, сообщение UI и очищенный logcat. Не публикуйте credentials/сырой полный лог.

Автотесты проверяют кликабельный/необрезанный путь, запрет действия в busy, intent MIME/content URI/read grant/ClipData и отсутствие NEW_TASK/file://. Они не доказывают запуск OEM installer, выдачу неизвестных источников или установку APK на реальной ТВ-приставке. Эти сценарии требуют device QA.


## LocProxyTV / 3.8.4

Изменено только отображаемое название. Репозиторий, URL GitHub API/Pages, applicationId `org.proxydroid`, FileProvider authority, signing certificate и технические префиксы APK сохранены для совместимости. Старые версии называются ProxyDroid; новые — LocProxyTV. Это не обход несовпадающих сертификатов.

На фотографии устройства установлена 3.8.1 / build 38071815647 и выбрана 3.8.2 ARM32 / build 38074611701. Независимые apksig-проверки опубликованных APK обеих сборок показывают один release signer `0749fd8dc3df58d0b268d95f7bd43110e8314fd07ad61edb5672ee1406977657`. Это подтверждает одинаковые подписи опубликованных файлов, но не заменяет чтение сертификата APK, реально установленного на приставке. Старый UI ошибку отсутствующего parser signingInfo не отличает от реального mismatch. Для перехода можно скачать новый подписанный APK через браузер и открыть системным установщиком поверх приложения, не удаляя его. Если Android тоже отказывает — остановиться и проверить установленный сертификат; не обходить защиту.
